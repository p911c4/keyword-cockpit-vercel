시작하기 — 블로그 설정

화면 우측 상단 설정 버튼에서 내 블로그 ID를 저장해 두면 세 가지 도구 전체에서 활용됩니다. 네이버 블로그 주소(blog.naver.com/아이디)에서 아이디 부분만 입력하면 되고, 전체 URL을 붙여넣어도 자동으로 추출됩니다. 설정값은 서버가 아닌 사용 중인 브라우저에만 저장되므로 다른 기기에서는 다시 설정해야 합니다.

① 키워드 분석 — 검색량과 트렌드 확인

  1. 메인 화면 입력창에 키워드를 입력하고 검색을 누릅니다.
  2. 월간 검색량(PC/모바일/합계)과 기기별 비율, 경쟁도가 카드로 표시됩니다.
  3. 최근 12개월 검색 트렌드 그래프에서 계절성과 성장·쇠퇴 흐름을 확인합니다. 그래프의 점에 마우스를 올리면 월별 상세 수치가 보입니다.
  4. 연관 키워드를 클릭하면 해당 키워드가 즉시 재분석됩니다 — 메인 키워드에서 세부 키워드로 확장해 나가는 가장 빠른 방법입니다.
  5. 블로그 ID를 설정해 두었다면 검색 키워드에 대한 내 블로그 포스팅과 네이버 상위 포스팅 10개가 함께 표시되어 경쟁 상황을 바로 비교할 수 있습니다.

활용 팁

결과 하단의 CSV 저장으로 여러 키워드를 엑셀에 모아 비교하면 콘텐츠 발행 우선순위를 정하기 좋습니다. 최근 검색한 키워드 5개는 태그로 남아 클릭 한 번으로 재조회할 수 있습니다.

구글 지표 읽는 법 — Google Ads 키워드 플래너

키워드 분석 화면의 소스 전환 버튼에서 구글 또는 통합을 고르면 Google Ads API(키워드 플래너)에서 받은 지표 4종이 함께 표시됩니다. 네이버 검색량 표와 섞지 않고 별도 카드로 분리했으며, 통합 보기에서는 같은 성격의 지표가 좌우로 마주보도록 배치했습니다.

표시되는 지표 4종

월간 검색량 (구간): 대한민국·구글 검색 기준 월평균 검색량입니다. 아래 "검색량을 구간으로 표시하는 이유"에서 설명하듯 정확한 수치가 아닌 범위(예: 10,000 ~ 100,000)로 제공됩니다.

경쟁도 지수 (0~100): 네이버의 낮음·중간·높음 3단계보다 세밀한 수치 지표입니다. 같은 "중간"이라도 32와 68은 전혀 다른 시장이므로, 경쟁 강도를 비교할 때 훨씬 유용합니다.

페이지 상단 입찰가: 해당 키워드로 검색 결과 상단에 광고를 노출하기 위해 광고주들이 실제로 지불한 입찰가 범위(원)입니다. 네이버 지표에는 없는 항목으로, 키워드의 상업적 가치를 금액으로 가늠할 수 있습니다. 입찰가가 높다는 것은 그 키워드로 유입된 방문자가 실제 구매로 이어질 확률이 높다는 뜻입니다.

12개월 계절성: 최근 1년 월별 검색량 추이입니다. 네이버 데이터랩 트렌드가 국내 상대 지표라면 이쪽은 구글 검색 기준이라, 두 검색엔진의 흐름 차이를 비교할 수 있습니다. 최고점 월과 최저 대비 배수를 함께 표시하므로 시즌 키워드인지 상시 키워드인지 한 줄로 판정됩니다.

검색량을 구간으로 표시하는 이유

구글 키워드 플래너는 광고 집행 실적이 없는 계정에 대해 검색량을 정확한 수치가 아닌 넓은 구간 단위로 제공합니다. 예를 들어 실제 검색량이 1,300회인 키워드와 9,400회인 키워드가 똑같이 "1,000 ~ 10,000" 구간으로 묶입니다.

이 값을 "월간 검색량 5,500회"처럼 하나의 숫자로 바꿔 표시하면 보기에는 깔끔하지만 사실과 다릅니다. 본 도구는 데이터가 가진 정밀도 이상으로 정확한 척 표시하지 않는다는 원칙에 따라 구간 그대로 표시합니다. 정확한 절대 수치가 필요한 경우에는 네이버 검색량을 기준으로 삼으시고, 구글 지표는 경쟁 강도와 상업적 가치를 판단하는 용도로 활용하세요.

표기 형식은 네이버와 맞춰 콤마 단위로 씁니다. 62,700 옆에 "1천 ~ 1만"이 놓이면 자릿수가 한눈에 잡히지 않기 때문입니다. 최근 검색 표에서는 두 검색엔진의 비중을 작은 막대로도 보여주는데, 이 막대의 폭 역시 화면에 표시된 구간에서만 계산합니다.

네이버 경쟁도와 구글 경쟁도는 같은 값이 아닙니다

두 지수는 0~100으로 같은 눈금을 쓰지만 산출 근거가 다릅니다. 네이버 경쟁도는 해당 키워드에 월평균 몇 개의 광고가 노출되는지를 환산한 값이고, 구글 경쟁도는 그 키워드에 입찰하는 광고주의 밀도입니다. 화면에서 두 게이지의 생김새를 일부러 다르게 그린 이유가 여기 있습니다 — 네이버는 칸을 세는 게이지, 구글은 위치를 가리키는 마커입니다. 두 숫자를 직접 빼거나 비교하지 마시고 각 검색엔진 안에서의 상대적 강도로 읽으세요.

화면 구성

통합 보기에서는 같은 성격의 지표가 같은 행에 놓입니다. 눈이 좌우로만 움직이도록 한 배치입니다.

  • 1행: 월간 검색량 (네이버 합계·PC·모바일 / 구글 구간·경쟁도·입찰가)
  • 2행: 경쟁도 지수 0~100 (네이버는 노출 광고 수 / 구글은 광고주 밀도)
  • 3행: 12개월 추이 (네이버 데이터랩 트렌드 / 구글 계절성)
  • 4행: 연관 키워드 (양쪽 모두 검색량순 상위 5개, 더보기로 15개까지)
  • 5행: 네이버 발행 현황 / 내 블로그 포스팅 — 이 행만 좌우가 모두 네이버 데이터입니다. 소스가 아니라 "시장 상황과 내 글"로 나뉩니다.

네 개 카드가 실제로 어떻게 보이는지 확인하세요. 통합 보기에서는 각각 1~4행의 오른쪽에 놓입니다.

구글 검색 순위(상위 10)는 왜 없나요

구글은 공개 검색 결과 페이지를 반환하는 공식 API를 제공하지 않습니다. 그나마 쓸 수 있던 Custom Search JSON API도 신규 이용이 중단됐고 2027년 1월 1일 종료됩니다.

검색 결과를 직접 수집하는 방식은 구글 약관에 어긋나므로 본 도구는 사용하지 않습니다. 대행 서비스를 통한 우회도 같은 이유로 쓰지 않습니다. Google Ads API를 정식으로 승인받아 운영 중인 도구가 약관 위반 소지가 있는 데이터를 함께 다루면, 지금 제공 중인 구글 지표 전체를 잃을 수 있기 때문입니다.

구글 쪽은 검색량·경쟁도·입찰가로 이 키워드에 시간을 쓸 가치가 있는지를 판단하는 데 씁니다.

네이버 블로그 상위 10도 일시 중단했습니다

네이버 블로그 검색 API의 정확도순(sort=sim) 결과가 실제 네이버 검색 노출 순서와 크게 어긋나는 현상이 확인되었습니다. 실제 검색에서 상위에 있는 글이 API 결과 100건 안에 아예 나타나지 않는 사례를 여러 키워드에서 확인했습니다.

틀린 순위를 보여주는 것이 순위를 보여주지 않는 것보다 나쁘다고 판단해 해당 카드를 잠시 내렸습니다. API가 정상화되면 복구합니다. 그동안은 아래 발행 현황으로 경쟁 강도를 가늠하실 수 있습니다.

중단 기간에는 그 자리에 발행 현황이 들어갑니다. 발행일 내림차순(sort=date)은 규칙이 단순해 해석 여지가 없으므로, 정확도순과 달리 신뢰할 수 있습니다.

  • 오늘 발행: 조회 시각까지 이 키워드로 올라온 네이버 블로그 글 수입니다. 하루가 진행 중인 값이라 아래 세 항목과 성격이 달라 따로 떼어 두었습니다. 100건을 넘으면 100건 이상으로만 표시합니다.
  • 100건 발행: 최근 100건이 쌓이는 데 걸린 시간입니다. 하루가 안 걸렸다면 약 15시간 소요처럼 시간 단위로 표시합니다 — 하루도 못 버티고 밀려난다는 뜻입니다.
  • 1,000건 발행: 같은 계산을 1,000건 기준으로 본 값입니다. 100건 값과 나란히 보면 최근 발행이 몰렸는지 알 수 있습니다 — 100건 12일에 1,000건 115일이면 하루 평균이 8.3편과 8.7편으로 거의 같아 안정된 시장이고, 100건 6일에 1,000건 20일이면 최근 급증한 것입니다. 하루 10편 미만은 소수 한 자리로 표시해 두 기준이 구분되게 했습니다.
  • 기회 지수: 아래 절에서 따로 설명합니다.

조회는 두 번입니다. 첫 페이지(100건)와 start=901 한 페이지만 보면 되므로, 사이 페이지를 훑지 않습니다. 네이버 블로그 검색은 start 상한이 1,000이라 그 너머는 볼 수 없고, 총 문서가 1,000건에 못 미치는 키워드는 두 번째 조회를 아예 건너뜁니다.

기회 지수 — 검색량만 보면 놓치는 것

검색량이 큰 키워드가 늘 유리하지는 않습니다. 수요가 커도 글이 그만큼 많으면 나눠 가질 몫이 적기 때문입니다. 기회 지수는 월간 검색량을 30일 환산 발행량으로 나눈 값으로, 수요 대비 공급이 얼마나 비어 있는지를 봅니다.

  • 매우 좋음: 편당 100회 이상 — 수요에 비해 글이 거의 없습니다
  • 좋음: 30~100회 — 신규 진입 여지가 있습니다
  • 보통: 10~30회 — 상위권이 아니면 유입이 어렵습니다
  • 포화: 10회 미만 — 검색량이 커도 몫이 적습니다
  • 수요 미미: 월간 검색량 100회 미만 — 등급을 매기지 않습니다. 공급이 많아서가 아니라 찾는 사람이 적어 편당 수치가 낮게 나오므로, 같은 값이라도 포화와는 정반대 상황입니다.

이 값은 편당 예상 유입이 아닙니다. 실제로는 상위 노출된 글이 대부분을 가져가므로 편차가 매우 큽니다. 시장이 얼마나 붐비는지를 가늠하는 용도로만 쓰시고, 수치를 작게 병기한 것도 정밀한 값이 아니기 때문입니다.

검색량은 네이버 전체 검색 수이고 발행량은 블로그 글 수라 모집단도 다릅니다. 카페·지식iN·플레이스는 빠져 있습니다. 30일 환산 발행량이 5편 미만이면 나눗셈이 불안정해 측정 불가로 표시합니다.

발행량은 소요 시간에서 역산합니다. 오늘 발행 수를 쓰지 않는 이유는 하루가 진행 중이기 때문입니다 — 새벽에 조회하면 적게, 밤에 조회하면 많게 나와 같은 키워드의 지수가 시각에 따라 달라집니다. 표본이 큰 1,000건 기준을 우선 쓰고, 없으면 100건 기준으로 계산합니다.

소요 시간은 소수로 계산합니다. 0.6일을 1일로 올리면 하루 평균이 158편에서 100편으로 왜곡되기 때문입니다. 다만 발행일 데이터에는 날짜만 있고 시각이 없어, 오늘 자정 이후 경과 시간만 실측하고 그 이전 날짜는 하루 단위로 셉니다.

구글 데이터 취급 방침

  • 키워드 아이디어 조회 한 가지 호출만 사용합니다. 계정이나 캠페인을 만들고 고치는 호출은 하지 않습니다.
  • 검색량은 구간으로만 표시하며, 정밀한 측정치처럼 제시하지 않습니다.
  • 구글 데이터는 CSV 내보내기에서 제외합니다. 화면에서 참고하는 것과 대량으로 내려받아 재배포하는 것은 다른 문제입니다.
  • 조회 결과는 최대 7일간 저장해 같은 키워드의 중복 호출을 줄이고, 하루 호출 상한을 둡니다.
  • 이용자의 구글 계정 연결을 요구하지 않으며, IP 주소를 저장하지 않습니다.
  • 구글 지표가 보이지 않는 화면에서는 구글 API를 호출하지 않습니다. 소스 전환으로 구글이나 통합을 선택한 시점에만 조회합니다.

② 블로그 지수 — 활동 지표

  1. 블로그 ID를 입력하고 조회하면 총 포스팅 수(추정), 최근 30일 발행 수, 활동 지수와 LV.1~9 등급 게이지가 표시됩니다.
  2. 하단 키워드 입력창의 노출 순위 조회는 현재 일시 중단 상태입니다. 네이버 블로그 검색 API의 정확도순 결과가 실제 검색 노출 순서와 크게 어긋나는 현상이 확인되어, 틀린 순위를 보여주지 않기로 했습니다. API가 정상화되면 복구합니다.

활용 팁

내 블로그뿐 아니라 벤치마킹 대상 블로그의 ID를 입력해 발행량을 비교해 보세요. 활동 지수 산정 방식과 등급표는 블로그 지수 페이지 하단의 지표 해설에서 확인할 수 있습니다.

③ 노출 레이더 — 포스팅 일괄 확인

  1. 스캔 시작 버튼을 누르면 최근 포스팅 최대 15개를 자동으로 불러와 순서대로 분석합니다.
  2. 각 포스팅의 해시태그에서 의도 키워드를 추출합니다. 다만 포스팅 지수는 현재 산출을 중단했습니다. 100점 중 45점이 노출 순위에 의존하는 구조라, 순위 없이 계산하면 잘 쓴 글도 낮은 점수로 눌리기 때문입니다.
  3. 결과는 5개씩 3개 페이지로 나뉘어 표시되며, 분석 중인 페이지는 모래시계, 완료된 페이지는 체크로 구분됩니다. 스캔 중 언제든 중단할 수 있습니다.

활용 팁

지수 산출이 복구되면 낮게 나온 포스팅이 리라이팅 후보가 됩니다 — 제목 앞부분에 핵심 키워드를 배치하고, 검색량이 있는 해시태그로 재정비한 뒤 내용을 보강하세요. API 호출 제한 준수를 위해 포스팅마다 몇 초씩 소요되는 것은 정상 동작입니다. 지수 산정 원리와 등급표는 노출 레이더 페이지 하단에서 확인할 수 있습니다.

추천 워크플로

세 도구를 이 순서로 쓰면 효과적입니다. ① 키워드 분석으로 검색량이 있으면서 경쟁도가 낮은 키워드를 발굴하고 → ② 그 키워드로 글을 발행한 뒤 블로그 지수에서 노출 여부를 확인하고 → ③ 주기적으로 노출 레이더를 돌려 지수가 떨어진 포스팅을 찾아 리라이팅하는 순환 구조입니다. 발행 → 측정 → 개선의 사이클을 데이터로 관리하는 것이 이 도구의 핵심 활용법입니다.
